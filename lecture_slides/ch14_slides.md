## 第2页: 大模型驱动的机器人范式

```
传统范式:                    大模型范式:
  人 → [命令解析] → 预编程 → 执行    人 → [自然语言] → LLM → 动态规划 → 执行
         (固定规则)                          (语义理解)

优势:
  ✓ 零样本泛化 — 无需为每个任务重新编程
  ✓ 自然语言交互 — 非专业人员可操作
  ✓ 常识推理 — 理解隐含的上下文
  ✓ 错误恢复 — 根据反馈调整策略

挑战:
  ✗ 延迟 — LLM 推理 ~1-5s
  ✗ 幻觉 — 可能输出不合理计划
  ✗ 安全性 — 生成的代码需要过滤
  ✗ 依赖网络 — 云端 API 依赖
```

## 第5页: Prompt Engineering (1/2)

**ROS 2 机器人场景最佳实践:**

```
1. 角色设定 (Role)
   "你是一个仓库机器人专家..."
   → 限定行为边界, 提高专业性

2. 环境上下文 (Context)
   "坐标范围 x:[-5,5], 已知地点: ..."
   → 减少幻觉, 输出更精确

3. 能力声明 (Capabilities)
   "你可以: navigate, pick, place, detect"
   → 限制操作范围, 避免不可执行的任务

4. 输出格式 (Format)
   "必须返回合法 JSON..."
   → 便于程序解析

5. 安全约束 (Safety)
   "不能进入禁区, 禁止危险动作"
   → 防止不安全行为

6. Few-shot 示例
   输入示例 → 输出示例 (2-3组)
   → 提高格式一致性
```

## 第6页: Prompt Engineering (2/2)

**任务规划 System Prompt 模板:**

```
System:
你是仓库机器人 Alpha。你可以:
1. navigate(location): 移动到指定地点
2. detect(object_class): 视觉检测物体
3. pick(object_name): 抓取指定物体
4. place(location): 在指定位置放置物体
5. speak(text): 语音播报

环境:
- 仓库 10m×10m
- 已知地点: entrance(0,0), shelf_a(2,2),
  shelf_b(-2,2), desk(3,-1), station(0,-3)
- 禁止入内: [充电区, 维修区]

安全规则:
- 移动前确认路径无人员
- 最大速度 0.5m/s
- 连续3次失败后报告并停止

输出格式:
{"plan": [{"step":1,"action":"...","args":{}},...],
 "estimated_time": 秒数,
 "safety_check": "已检查"}

User:
去 shelf_a 拿一个瓶子送到 desk
```

## 第7页: Code as Policies (CaP)

```
传统方法: LLM → 任务序列 → 解释器 → 执行
  (输出抽象计划, 需预定义动作集)

CaP: LLM → Python 代码 → 直接执行
  (输出可执行代码, 灵活度更高)

示例:
  输入: "去三个货架巡检, 每个停留3秒"
  
  LLM 生成:
  ```python
  robot.move_to(2.0, 2.0)   # shelf_a
  robot.spin(360)            # 巡检
  time.sleep(3)
  robot.move_to(-2.0, 2.0)   # shelf_b
  robot.spin(360)
  time.sleep(3)
  robot.move_to(0.0, -3.0)   # station
  robot.spin(360)
  ```
```

**CaP 安全性:**
- 代码沙箱执行 (子进程隔离)
- 禁止关键字过滤
- 超时机制
- 人工审核模式 (可选)

## 第10页: 安全与可靠性设计

```
LLM 安全机制分层:

Layer 1: Prompt 约束
  - 明确禁止的操作
  - 安全优先级声明

Layer 2: 输出过滤
  - 代码黑名单关键字
  - JSON schema 验证

Layer 3: 执行沙箱
  - 子进程隔离
  - 资源限制 (CPU/内存)
  - 超时机制 (30s)

Layer 4: 机器人层安全
  - 代价地图碰撞检测
  - 软急停 (soft e-stop)
  - 速度/力限制

Layer 5: 人工监督
  - 关键操作人工确认
  - 执行日志可追溯
  - 一键停止
```

## 第11页: 端到端延迟分析

```
典型仓库巡检任务端到端延迟:

文本输入 → LLM 规划      2.0s  (API 调用)
         → Action 解析   0.05s
         → Nav2 导航     15.0s (移动 ~3m)
         → YOLO 检测     0.1s  (目标检测)
         → VLM 验证      2.5s  (API + 图像传输)
         → 任务报告      1.0s  (TTS)

总计: ~20s (其中机器人移动占主导)

优化策略:
  - 导航 + 检测并行 (流式)
  - 本地模型降低 LLM/VLM 延迟
  - 预规划 + 缓存常见任务
```
