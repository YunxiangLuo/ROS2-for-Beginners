## 学习目标

本章学习目标包括：理解多传感器融合定位的必要性，掌握松耦合、紧耦合、深耦合三种融合策略的区别；掌握扩展卡尔曼滤波（EKF）的预测-更新两阶段结构、15 维状态向量设计与协方差传播方法；学会基于 robot_localization 搭建 LiDAR-IMU-GNSS 松耦合融合系统，掌握传感器频率对齐与 TF2 坐标树设计要点；理解马氏距离异常检测对融合鲁棒性的作用；能够获取 CARLA Ground Truth 真值，并使用 evo 工具按 ATE/RPE 指标完成定位精度的标准化评估。

## 41.1 定位技术概述

自动驾驶中定位系统是感知与决策的基石。单一传感器无法在所有场景下提供可靠定位，因此多传感器融合成为必然选择。

### 41.1.1 传感器定位方案对比

| 特性 | GNSS (GPS/RTK) | IMU (惯性) | LiDAR (激光) | 视觉 (Camera) |
|------|----------------|------------|---------------|---------------|
| **精度** | 米级~厘米级(RTK) | 航姿精确, 位置发散 | 厘米级 | 米级~分米级 |
| **频率** | 1~20 Hz | 100~1000 Hz | 10~20 Hz | 15~60 Hz |
| **长期稳定性** | 好 (无漂移) | 差 (积分漂移) | 好 (地图匹配) | 中 (受光照影响) |
| **短期稳定性** | 差 (多径/遮挡) | 好 (高频) | 好 | 好 |
| **环境依赖** | 需卫星信号 | 无外部依赖 | 需特征结构 | 需光照/纹理 |
| **成本** | 低~高 | 低~高 | 高 | 低 |
| **主要缺陷** | 隧道/高楼遮挡 | 零偏随时间累积 | 退化场景(长走廊) | 光照变化/动态 |

### 41.1.2 融合定位策略

常见的融合定位策略可分为三类：**松耦合 (Loosely Coupled)** 中各传感器独立输出位姿估计，在状态估计层完成融合；**紧耦合 (Tightly Coupled)** 直接在原始观测层融合伪距、特征点等观测；**深耦合 (Deeply Coupled)** 则在信号层面融合，多见于 GNSS+IMU 组合。

本章采用 **松耦合 EKF 架构**, 融合 LiDAR SLAM 位姿、IMU 预积分、GNSS 定位解。

### 41.1.3 官方要点——FAST-LIO2 与紧耦合前沿：从松耦合到激光惯性里程计

本章 41.1 的融合策略对比中「紧耦合」一档的国际代表是港大 MARS 实验室的 FAST-LIO2（官方仓库 hku-mars/FAST_LIO）：其核心是把原始点云特征直接纳入迭代 EKF（iterated EKF）观测方程、配合 ikd-tree 增量式地图维护，实现「无预建图、直接里程计」，官方报告在中速场景下达厘米级精度——与松耦合 EKF（robot_localization）的关系类似「深度耦合观测 vs 分传感器预处理」。官方 README 同时给出消融实验：去掉 IMU 后鲁棒性显著下降，印证了 41.3.1 松耦合架构中「IMU 高频桥接」的必要性。建议读者把 41.4 的 CARLA 数据按 TUM 格式导出后，用 evo 评估 robot_localization 基线，再对照 FAST-LIO2 论文的指标表理解两类方法差距。

## 41.2 扩展卡尔曼滤波 (EKF)

### 41.2.1 算法流程

```
┌─────────────────────────────────────────────────────┐
│                    EKF 融合流程                        │
├─────────────────────────────────────────────────────┤
│                     初始化                             │
│               x₀, P₀, Q, R  (k=0)                    │
│                         │                             │
│                    ┌────▼────┐                       │
│                    │ 预测步   │ (IMU 驱动)             │
│                    │ x̄ₖ = f(x̂ₖ₋₁, uₖ)               │
│                    │ P̄ₖ = F·Pₖ₋₁·Fᵀ + Q            │
│                    └────┬────┘                       │
│                         │                             │
│           ┌─────────────┼─────────────┐               │
│           ▼             ▼             ▼               │
│      LiDAR 观测    GNSS观测    其他观测               │
│    z_ℓ ~ N(0,R_ℓ)  z_g ~ N(0,R_g)                    │
│           │             │                             │
│           ▼             ▼                             │
│    ┌──────────────────────────┐                       │
│    │     更新步 (迭代观测)     │                       │
│    │ Kₖ = P̄ₖ·Hᵀ(H·P̄ₖ·Hᵀ+R)⁻¹ │                       │
│    │ x̂ₖ = x̄ₖ + Kₖ(zₖ − h(x̄ₖ)) │                       │
│    │ Pₖ = (I − Kₖ·H)P̄ₖ      │                       │
│    └──────────────────────────┘                       │
│                         │                             │
│                    ┌────▼────┐                       │
│                    │ 输出 x̂ₖ  │                       │
│                    │ k = k+1  │                       │
│                    └─────────┘                       │
└─────────────────────────────────────────────────────┘
```

### 41.2.2 状态向量设计

本节使用 15 维 EKF 状态 (robot_localization 标准模式):

```
x = [x, y, z,            ← 位置 (m)
     roll, pitch, yaw,   ← 姿态 (rad)
     vx, vy, vz,         ← 线速度 (m/s)
     wx, wy, wz,         ← 角速度 (rad/s)
     ax, ay, az]ᵀ        ← 线加速度 (m/s²)
```

### 41.2.3 状态转移模型 (预测)

$$
\begin{aligned}
p_{k} &= p_{k-1} + v_{k-1} \Delta t + \frac{1}{2} a_{k-1} \Delta t^2 \\
v_{k} &= v_{k-1} + a_{k-1} \Delta t \\
q_{k} &= q_{k-1} \otimes \exp\left(\frac{\omega_{k-1} \Delta t}{2}\right) \\
a_{k} &= a_{k-1} + n_a, \quad \omega_{k} = \omega_{k-1} + n_\omega
\end{aligned}
$$

### 41.2.4 协方差矩阵

预测阶段协方差传播:

```
P̄ₖ = F · Pₖ₋₁ · Fᵀ + Q

其中:
  F: 状态转移雅可比 (15×15)
  Q: 过程噪声协方差矩阵
     Q = blkdiag(Q_p, Q_q, Q_v, Q_ω, Q_a)
     
  Q_p = σ_p²·I₃ (位置噪声)
  Q_q = σ_q²·I₃ (姿态噪声)  
  Q_v = σ_v²·I₃ (速度噪声)
  Q_ω = σ_ω²·I₃ (角速度噪声)
  Q_a = σ_a²·I₃ (加速度噪声)
```

观测更新协方差:

```
R = blkdiag(R_lidar, R_gnss, R_imu)
  R_lidar = diag(σ_xy², σ_xy², σ_z², σ_rp², σ_rp², σ_yaw²)
  R_gnss  = diag(σ_gnss², σ_gnss², σ_gnss²)
```

### 41.2.5 官方要点——卡尔曼滤波的文献源头与状态估计课程主线

R. E. Kalman 1960 年的原始论文《A New Approach to Linear Filtering and Prediction Problems》奠定了滤波框架，EKF 则是其对非线性系统的雅可比线性化扩展——本章 41.2 的预测-更新两阶段结构、协方差传播与增益计算，正是该文献的国际标准教学表述。多伦多大学在 Coursera 开设的《State Estimation and Localization for Self-Driving Cars》课程是这一主题最常被引用的体系化课程：从最小二乘 → EKF → 手眼标定 → LiDAR/IMU/GNSS 松耦合，每周配套编程作业，其作业设计与本章 41.3 的「IMU 高频预测 + GNSS/LiDAR 低频修正」流程完全同构，适合作为课后进阶练习。

### 41.3.2 传感器频率对齐策略

| 传感器 | 原始频率 | EKF 接收方式 | 说明 |
|--------|---------|-------------|------|
| IMU | 100~200 Hz | 预测步驱动 | 每个IMU消息触发一次预测 |
| LiDAR SLAM | 10~20 Hz | 位姿观测更新 | 触发完整6-DOF位置姿态更新 |
| GNSS | 1~10 Hz | 位置观测更新 | 仅更新x/y/z分量 |

### 41.3.3 TF2 坐标树设计

```
map ──(static)──▶ odom ──(EKF)──▶ base_link
                                   │
                          ┌────────┼────────┐
                          ▼        ▼        ▼
                      lidar_link  imu_link  gps_link
                     (static)   (static)   (static)

坐标系说明:
  map:       世界固定坐标系 (UTM/高斯投影)
  odom:      里程计坐标系, 无累计漂移的连续参考系
  base_link: 车辆本体坐标系 (后轴中心)
  lidar_link: LiDAR 安装位置
  imu_link:   IMU 安装位置  
  gps_link:  GNSS 天线相位中心

变换关系:
  map→odom: 初始化时确定, 之后odom在map中漂移
  odom→base_link: EKF 估计的相对位姿 (无跳变)
  base_link→sensor: 通过 URDF 标定的固定变换
```

### 41.3.4 协方差阈值与异常检测

```python
# 融合策略伪代码
def fuse_sensor_data(ekf, measurement):
    # 马氏距离异常检测
    innovation = measurement.z - ekf.h(ekf.x)
    S = ekf.H @ ekf.P @ ekf.H.T + measurement.R
    mahalanobis = innovation.T @ np.linalg.inv(S) @ innovation
    
    if mahalanobis > CHI2_95[measurement.dim]:
        logger.warn(f"异常观测丢弃: χ²={mahalanobis:.2f}")
        return ekf  # 拒绝异常观测
    
    return ekf.update(measurement)
```

### 41.3.5 官方要点——robot_localization 官方文档：融合配置与 REP-105 纪律

robot_localization 官方文档是 41.3 松耦合架构的工业级实现参照：官方模板 `ekf.yaml` 中每个传感器以 `odom0`/`imu0`/`pose0` 前缀接入，`odom0_config` 用 15 维布尔掩码（x/y/z、roll/pitch/yaw、线/角速度各 3 维）声明该传感器提供哪些分量——官方明确警告「同一时刻不要让两个传感器同提供绝对位姿」，否则协方差冲突导致抖动。官方文档同时强制 REP-105 坐标系纪律：`map → odom → base_link` 三级树，`map` 与 `odom` 之间由滤波器发布、`odom` 与 `base_link` 之间由里程计发布，本章 41.3.3 的 TF2 设计即此规范的仿真版。官方还建议滤波频率设为传感器最高频率（IMU 常见 100–200 Hz）并用 `differential` 参数区分位姿与速度融合。

## 41.4 CARLA Ground Truth 对比

### 41.4.1 获取 CarlaActor 真值

CARLA 通过 `carla.Actor.get_transform()` 和 `carla.Actor.get_velocity()` 提供毫米级精度的真值。

```python
# CARLA 真值订阅示例
class CarlaGtNode(Node):
    def __init__(self):
        super().__init__('carla_gt_node')
        self.sub = self.create_subscription(
            CarlaActor, '/carla/ego_pose', self.gt_callback, 10)
        self.gt_pub = self.create_publisher(
            Odometry, '/carla/ground_truth', 10)
    
    def gt_callback(self, msg):
        odom = Odometry()
        odom.header.stamp = self.get_clock().now().to_msg()
        odom.header.frame_id = 'map'
        odom.pose.pose = msg.pose  # CARLA 绝对位姿 (map系)
        odom.twist.twist = msg.twist
        self.gt_pub.publish(odom)
```

### 41.4.2 精度评估指标

| 指标 | 全称 | 公式 | 含义 |
|------|------|------|------|
| **ATE** | Absolute Trajectory Error | $\frac{1}{N}\sum\|p_{est,i} - p_{gt,i}\|$ | 绝对轨迹偏差 |
| **ATE RMSE** | ATE Root Mean Square Error | $\sqrt{\frac{1}{N}\sum\|p_{est,i} - p_{gt,i}\|^2}$ | 均方根绝对误差 |
| **RPE** | Relative Pose Error | $\frac{1}{M}\sum\|(p_{est,i}^{-1}p_{est,i+\Delta})^{-1}(p_{gt,i}^{-1}p_{gt,i+\Delta})\|$ | 相对位姿漂移 |
| **RPE trans** | RPE Translation | RPE 的平移分量 | 距离漂移 |
| **RPE rot** | RPE Rotation | RPE 的旋转分量 | 角度漂移 |

### 41.4.3 评估流程

┌──────────┐    ┌──────────────┐    ┌───────────┐

     │                 │                  │
     └─────────┬───────┘                  │
               ▼                          │
       时间戳对齐 (线性插值)                │
               │                          │
               ▼                          │

               │
               ▼
         ┌──────────┐

### 41.4.4 使用 evo 工具评估

```bash
# 保存轨迹
ros2 bag record -o localization_eval /carla/ground_truth /odometry/filtered

# 转换为 TUM 格式
evo_traj bag localization_eval.db3 /odometry/filtered --save_as_tum
evo_traj bag localization_eval.db3 /carla/ground_truth --save_as_tum

# ATE 评估
evo_ape tum ground_truth.tum filtered_odometry.tum -a --plot --plot_mode xy

# RPE 评估
evo_rpe tum ground_truth.tum filtered_odometry.tum -a --delta 1.0 --plot
```

### 41.4.5 典型精度目标 (CARLA 场景下)

| 场景 | ATE RMSE 目标 | RPE (每米) |
|------|--------------|------------|
| 高速路 (直线+弯道) | < 0.30 m | < 0.05 m/m |
| 城区 (有GNSS) | < 0.20 m | < 0.03 m/m |
| 隧道/LiDAR退化 | < 0.80 m | < 0.10 m/m |
| 停车场 (无GNSS) | < 0.50 m | < 0.08 m/m |

### 41.4.6 官方要点——evo 官方工具：ATE/RPE 的标准定义与评测姿势

41.4 的精度评估指标有一套国际通用的官方实现——evo 工具（Michael Grupp 维护）：`evo_ape` 计算绝对位姿误差（ATE，含平移/旋转分量），`evo_rpe` 计算相对位姿误差（RPE，常按固定间隔 1 m 或 1 s 分窗），并内置 Umeyama 刚体对齐（`-a`）与尺度校正（`-s`）以消除坐标系差异——官方文档明确提醒：**未对齐前直接比较两条轨迹是常见错误**。evo 还支持 TUM/KITTI/EuRoC 三种轨迹文件格式互转，并可用 `--plot` 可视化误差曲线，与 41.4.4 的评估流程配合使用可把 CARLA 真值与估计轨迹的对比标准化。

## 总结

多传感器融合定位通过互补各传感器优势实现鲁棒定位；EKF 是工业界应用最广泛的融合框架，预测-更新结构清晰；松耦合架构灵活易实现，robot_localization 提供了成熟方案；TF2 坐标树设计是定位系统的基础，需要严格定义坐标系变换；CARLA Ground Truth 为定位精度评估提供了理想基准，ATE/RPE 则是评估定位精度的标准指标。
