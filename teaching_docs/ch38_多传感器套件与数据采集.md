### 38.1.3 内参矩阵与畸变模型

相机内参矩阵K将3D世界坐标投影到2D像素平面：

```
K = [fx   0   cx]
    [0   fy   cy]
    [0    0    1]
```

其中，fx、fy为焦距（像素单位），满足 `fx = F * image_size_x / sensor_width`；cx、cy为主点坐标，通常位于图像中心。

```python
# 从CARLA相机中获取内参
def get_camera_intrinsics(camera_actor, image):
    h, w = image.height, image.width
    fov = camera_actor.attributes['fov']
    fov = float(fov)

    fx = w / (2.0 * math.tan(fov * math.pi / 360.0))
    fy = h / (2.0 * math.tan(fov * math.pi / 360.0))
    cx = w / 2.0
    cy = h / 2.0

    K = np.array([[fx, 0, cx],
                  [0, fy, cy],
                  [0,  0,  1]])
    return K
```

CARLA相机默认使用 **针孔模型(pinhole model)**，无畸变(畸变系数为0)。如需模拟真实相机畸变，可在后处理中添加：

```python
# 模拟径向畸变
def apply_distortion(image_np, k1=0.05, k2=0.02):
    h, w = image_np.shape[:2]
    K = np.array([[w/2, 0, w/2],
                  [0, h/2, h/2],
                  [0, 0, 1]])

    mapx, mapy = cv2.initUndistortRectifyMap(
        K, np.array([k1, k2, 0, 0, 0]),
        None, K, (w, h), cv2.CV_32FC1
    )
    return cv2.remap(image_np, mapx, mapy, cv2.INTER_LINEAR)
```

### 38.1.4 Depth与Semantic Segmentation数据处理

Depth相机输出需要进行解码才能得到实际距离：

```python
# Depth图像解码（CARLA编码方式）
def decode_depth_image(raw_data):
    import numpy as np
    # raw_data: 4-ch BGRA, depth编码在R/G/B通道
    data = np.frombuffer(raw_data, dtype=np.uint8)
    data = data.reshape((raw_data.height, raw_data.width, 4))
    data = data[:, :, :3]  # 取BGR通道

    # 解码: (R + G*256 + B*256*256) / (256*256*256 - 1) * 1000
    depth = data[:, :, 2] * 256 * 256 + data[:, :, 1] * 256 + data[:, :, 0]
    depth = depth / (256 * 256 * 256 - 1)
    depth = depth * 1000.0  # 转换为米
    return depth

# Semantic Segmentation标签映射
# 0: 未标注, 1: 建筑, 2: 围栏, 3: 其他, 4: 行人, 5: 路杆
# 6: 道路, 7: 人行道, 8: 植被, 9: 车辆, 10: 墙, 11: 交通标志
```

### 38.2.2 点云格式与处理

LiDAR传感器输出为原始点云数据，需转换为标准格式：

```python
import numpy as np

def lidar_raw_to_pointcloud(raw_data):
    """
    将CARLA LiDAR原始数据转换为Nx4的numpy数组
    每行: [x, y, z, intensity]
    """
    points = np.frombuffer(raw_data.raw_data, dtype=np.float32)
    points = points.reshape(-1, 4)

    # 坐标系转换: CARLA (x前, y右, z上) -> ROS (x前, y左, z上)
    # CARLA的Y轴与ROS相反
    points[:, 1] = -points[:, 1]

    return points

def pointcloud_to_ros2_msg(points, timestamp, frame_id='lidar_link'):
    """numpy点云 → sensor_msgs/PointCloud2"""
    from sensor_msgs.msg import PointCloud2, PointField

    msg = PointCloud2()
    msg.header.stamp = timestamp
    msg.header.frame_id = frame_id
    msg.height = 1
    msg.width = points.shape[0]
    msg.fields = [
        PointField(name='x', offset=0, datatype=PointField.FLOAT32, count=1),
        PointField(name='y', offset=4, datatype=PointField.FLOAT32, count=1),
        PointField(name='z', offset=8, datatype=PointField.FLOAT32, count=1),
        PointField(name='intensity', offset=12, datatype=PointField.FLOAT32, count=1),
    ]
    msg.is_bigendian = False
    msg.point_step = 16
    msg.row_step = msg.point_step * msg.width
    msg.is_dense = True
    msg.data = points.tobytes()
    return msg
```

```python
# IMU → ROS2 Imu
from sensor_msgs.msg import Imu

def imu_to_ros2_msg(imu_data, timestamp):
    msg = Imu()
    msg.header.stamp = timestamp
    msg.header.frame_id = 'imu_link'

    # 加速度 (m/s^2)
    msg.linear_acceleration.x = imu_data.accelerometer.x
    msg.linear_acceleration.y = -imu_data.accelerometer.y
    msg.linear_acceleration.z = imu_data.accelerometer.z

    # 角速度 (rad/s)
    msg.angular_velocity.x = imu_data.gyroscope.x
    msg.angular_velocity.y = -imu_data.gyroscope.y
    msg.angular_velocity.z = imu_data.gyroscope.z

    # 朝向 (由加速度计和陀螺仪融合)
    msg.orientation.w = imu_data.compass
    return msg
```

### 38.3.4 官方要点——官方传感器模型：从参数到噪声的忠实复现

CARLA 官方《Sensors》文档为每类传感器给出了标准参数集，与本章 38.1–38.3 完全对应：RGB 相机（fov、image_size_x/y、sensor_tick）、深度相机（深度编码为 RGB 通道，需按官方公式解码）、语义分割（cityscapes 标签集）、LiDAR（channels、range、points_per_second、dropoff 丢点率——官方用 `dropoff_general_rate` 模拟反射缺失）、RADAR（longitudinal/lateral_azimuth_angle、velocity_range 与官方信号处理模型）以及 GNSS（噪声正态分布 `noise_alt_bias` 等）与 IMU（`noise_accel_stddev`、`noise_gyro_stddev`）。官方强调：所有噪声参数都是统计模型而非物理模型，数据采集前必须「固定随机种子」才可复现实验——这正是 38.2.3 噪声模型配置一节的设计基准，也是 38.5.3 数据集管理「可复现性」的官方来源。

### 38.4.3 sensor_tick与同步

`sensor_tick`控制传感器数据发布的频率。值为0表示每个仿真步长都发布：

| sensor_tick | 行为 |
|-------------|------|
| 0.0 | 每个仿真步长触发回调 |
| 0.05 | 20Hz固定频率 |
| 0.1 | 10Hz固定频率 |
| 0.033 | ~30Hz固定频率 |

```python
# 多传感器时间同步
# CARLA中通过world.on_tick()获取全局时间戳
def setup_synchronized_sensors(world, sensors, callback):
    def tick_callback(world_snapshot):
        timestamp = world_snapshot.timestamp
        for sensor in sensors:
            sensor.listen(lambda data: callback(data, timestamp))

    world.on_tick(tick_callback)
```

### 38.4.4 坐标系对齐

CARLA与ROS坐标系约定对比：

| 方向 | CARLA | ROS |
|------|-------|-----|
| X | 前 | 前 |
| Y | 右 | 左 |
| Z | 上 | 上 |

```python
# CARLA → ROS 坐标转换
def carla_to_ros_transform(carla_transform):
    """将CARLA Transform转换为ROS TF2 Transform"""
    location = carla_transform.location
    rotation = carla_transform.rotation

    # ROS中Y轴取反
    ros_x = location.x
    ros_y = -location.y
    ros_z = location.z

    # 欧拉角 → 四元数 (ROS中Yaw取反)
    import math
    roll = math.radians(rotation.roll)
    pitch = math.radians(rotation.pitch)
    yaw = math.radians(-rotation.yaw)

    cy = math.cos(yaw * 0.5)
    sy = math.sin(yaw * 0.5)
    cp = math.cos(pitch * 0.5)
    sp = math.sin(pitch * 0.5)
    cr = math.cos(roll * 0.5)
    sr = math.sin(roll * 0.5)

    qw = cy * cp * cr + sy * sp * sr
    qx = cy * cp * sr - sy * sp * cr
    qy = sy * cp * sr + cy * sp * cr
    qz = sy * cp * cr - cy * sp * sr

    return ros_x, ros_y, ros_z, qx, qy, qz, qw
```

### 38.4.5 官方要点——相机标定的官方路线：OpenCV 与 ROS 工具链

### 38.5.2 数据同步与时间戳对齐

```python
def sync_callback(rgb_msg, depth_msg, lidar_msg, gnss_msg):
    """ApproximateTimeSynchronizer同步回调"""
    # 所有消息时间戳对齐
    stamp = rgb_msg.header.stamp

    # 保存到数据集
    dataset_entry = {
        'timestamp': stamp.sec + stamp.nanosec * 1e-9,
        'rgb': rgb_msg,
        'depth': depth_msg,
        'lidar': lidar_msg,
        'gnss': gnss_msg
    }
    return dataset_entry

# ROS2 ApproximateTime同步策略
from message_filters import ApproximateTimeSynchronizer, Subscriber

def setup_synchronizer(node, topics, queue_size=10, slop=0.05):
    subs = [Subscriber(node, msg_type, topic)
            for msg_type, topic in topics]
    sync = ApproximateTimeSynchronizer(
        subs, queue_size, slop, allow_headerless=False
    )
    sync.registerCallback(sync_callback)
    return sync
```

### 38.5.5 官方要点——时间同步的官方推荐：message_filters 与 sensor_tick

ROS 2 官方消息过滤文档对多传感器融合给出明确建议：精确同步（`ExactTime`）要求时间戳完全一致、仅适合确定时延链路；真实采集一律用 `ApproximateTimeSynchronizer`（本章 38.5.4 与 38.2.2 即此模式），官方注明其滑窗匹配算法在传感器时钟漂移下更稳健。官方同时给出工程建议：同一设备总线上的传感器统一 `sensor_tick`（CARLA 中同步模式 + 相同 sensor_tick 才能让时间戳对齐，见 38.4.3），话题 QoS 选 `BEST_EFFORT` + 小队列深度避免图像迟到反压——这是 38.5.1 rosbag 采集质量的前提。

### 38.5.6 官方要点——rosbag2 官方数据工作流与数据集管理

ROS 2 官方 rosbag2 文档定义了标准数据工作流：`rosbag2` 默认按 `storage plugin`（SQLite3）组织，录包目录含 `metadata.yaml`（录制时长、消息计数、话题 QoS 记录）；官方建议录制时写明 `--include` 话题白名单并开启 `--compression-mode file` 压缩，回放统一用 `rosbag2 play --rate 0.2` 慢速调试——与 38.5.1/38.5.4 对应。官方文档还强调「bag 即数据集」：元数据中 QoS 历史（依赖项）必须一起归档，换机回放时先 `ros2 bag info` 校验完整性再进算法，这正是 38.5.3 数据集管理章节的官方实践。Robotics Back-End 的进阶教程则演示了从 bag 抽取图像/点云为 PNG/PCD 的离线分析流程，与 38.5.2 时间戳对齐问题形成互补。

## 本章小结

本章介绍了CARLA多传感器套件与数据采集的核心内容：CARLA提供RGB、Depth与Semantic Segmentation三种相机，可通过sensor_tick控制采样频率；LiDAR支持通道数、FOV、丢点率等参数配置，输出Nx4格式点云；RADAR输出目标级检测，GNSS输出经纬度，IMU输出六轴加速度与角速度。传感器标定包含内参（传感器内部参数）和外参（传感器间空间变换）两部分，CARLA与ROS坐标系差异需进行转换（Y轴取反），并通过TF2进行坐标系管理。在数据采集方面，使用rosbag record采集数据，通过ApproximateTimeSynchronizer实现多传感器时间戳对齐。
