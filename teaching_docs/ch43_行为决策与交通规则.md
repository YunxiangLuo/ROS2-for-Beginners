# 第43章 行为决策与交通规则

行为决策是自动驾驶系统的"大脑"——它根据感知结果和环境信息，决定车辆下一秒应该执行什么驾驶行为。本章将深入讲解行为决策的核心算法，结合CARLA仿真平台实现交通规则感知与响应。

---

## 43.1 行为决策概述

### 43.1.1 分层决策架构

自动驾驶决策系统通常采用分层架构，从上到下依次为：

```
+---------------------------------------------------+
|  任务规划 (Route Planning)                         |
|  全局路径: A → B, 考虑道路网络、交通规则、拥堵    |
+---------------------------------------------------+
          ↓ 全局路径 (+ 车道级路线)
+---------------------------------------------------+
|  行为决策 (Behavioral Decision)                    |
|  巡航 / 跟车 / 变道 / 停车 / 避障 / 超车          |
|  有限状态机 (FSM) 或 行为树 (Behavior Tree)       |
+---------------------------------------------------+
          ↓ 驾驶行为 + 目标车道 + 目标速度
+---------------------------------------------------+
|  运动规划 (Motion Planning)                        |
|  生成平滑、无碰撞的轨迹 (路径 + 速度曲线)         |
|  常用算法: A*, RRT*, Lattice Planner, DWA         |
+---------------------------------------------------+
          ↓ 轨迹点 (x, y, θ, v, a, t)
+---------------------------------------------------+
|  控制 (Control)                                    |
|  PID, MPC 跟踪轨迹 → 油门/刹车/转向            |
+---------------------------------------------------+
```

- **行为规划** (Behavioral Planning)：离散的驾驶决策（如"跟车"、"变道"），时间尺度 100ms~1s。
- **运动规划** (Motion Planning)：连续的轨迹生成，时间尺度 10ms~100ms。

### 43.1.2 关键输入与输出

| 输入 | 说明 |
|------|------|
| 定位信息 | 自车位置、朝向、速度 |
| 车道信息 | 车道中心线、车道宽度、车道类型 |
| 障碍物 | 车辆、行人、骑行者等动态物体 |
| 交通标志 | 红绿灯、限速牌、停止标志 |
| 全局路径 | 任务规划给出的目标路线 |

| 输出 | 说明 |
|------|------|
| 目标行为 | `FOLLOW_LANE`, `CHANGE_LEFT`, `STOP` 等 |
| 目标速度 | 期望行驶速度 (m/s) |
| 目标车道 | 变道目标车道索引 |

## 43.2 有限状态机 (FSM)

### 43.2.1 状态定义

行为决策最经典的实现方式是**有限状态机 (Finite State Machine, FSM)**。我们将自动驾驶行为划分为以下状态：

| 状态 | 英文 | 说明 |
|------|------|------|
| 巡航 | CRUISE | 车道保持，无前车时按限速行驶 |
| 跟车 | FOLLOW | 检测到前车，保持安全距离和速度 |
| 变道左 | CHANGE_LEFT | 向左变道（超车或绕行） |
| 变道右 | CHANGE_RIGHT | 向右变道（让行或出口） |
| 停车 | STOP | 红灯、停止线、行人前停车 |
| 避障 | AVOID | 动态/静态障碍物紧急避让 |
| 完成 | COMPLETE | 到达目的地 |

### 43.2.2 状态转移图

```
                         +----------+
            +----------->+  CRUISE  +<-----------+
            |            +----+-----+            |
            |                 |                  |
     前车接近         绿灯/无障碍         前车切入
            |                 |                  |
            v                 v                  |
       +--------+       +----------+     +-------------+
       | FOLLOW +------>+   STOP   +---->+ CHANGE_LEFT |
       +--------+       +----------+     +-------------+
            |                 |                  |
     前车消失         红灯/行人           变道完成
            |                 |                  |
            +------+    +----+-----+            |
                   |    |          |            |
                   v    v          v            v
               +--------+   +-------------+
               | CRUISE |   | CHANGE_RIGHT|
               +--------+   +-------------+
```

### 43.2.3 状态转移表

| 当前状态 | 条件 | 下一状态 | 动作 |
|----------|------|----------|------|
| CRUISE | 前车距离 < 安全距离 | FOLLOW | 切换至跟车模式 |
| CRUISE | 红灯或行人 | STOP | 减速至停止 |
| CRUISE | 前车速度过慢且左道可行 | CHANGE_LEFT | 打左转向灯 |
| FOLLOW | 前车离开/消失 | CRUISE | 加速至巡航速度 |
| FOLLOW | 前车刹车 | FOLLOW | 同步减速 |
| STOP | 绿灯且无障碍 | CRUISE | 起步加速 |
| STOP | 红灯持续 | STOP | 保持停止 |
| CHANGE_LEFT | 变道完成/中止 | CRUISE | 回正方向 |
| AVOID | 避让完成 | CRUISE | 恢复巡航 |

### 43.2.4 FSM 实现要点

```python
class FsmState(Enum):
    CRUISE = 1
    FOLLOW = 2
    CHANGE_LEFT = 3
    CHANGE_RIGHT = 4
    STOP = 5
    AVOID = 6
    COMPLETE = 7

class BehaviorFSM:
    def __init__(self):
        self.state = FsmState.CRUISE
        self.transition_table = {
            FsmState.CRUISE: self._handle_cruise,
            FsmState.FOLLOW: self._handle_follow,
            FsmState.STOP:   self._handle_stop,
            ...
        }

    def update(self, perception):
        handler = self.transition_table[self.state]
        new_state, cmd = handler(perception)
        self.state = new_state
        return cmd
```

### 43.3.2 灯色分类与停止线判断

交通灯状态机：

```
          +---------+
          | UNKNOWN |  ← 初始化/未检测到
          +----+----+
               |
         检测到交通灯
               |
               v
        +-------------+
        | APPROACHING |  ← 接近路口，判断灯色
        +------+------+
               |
     +---------+---------+
     |         |         |
     v         v         v
 +------+ +--------+ +--------+
 | RED  | | YELLOW | | GREEN  |
 +--+---+ +----+---+ +---+----+
    |         |         |
    |   黄灯剩余>3s      |
    +----+----+---------+
         |         |
      减速停止   匀速通过
         v         v
      +------+  +--------+
      | STOP |  | CRUISE |
      +------+  +--------+
```

判断停止线距离：

```python
def should_stop_for_traffic_light(vehicle, traffic_light, stop_margin=3.0):
    """判断车辆是否需要在交通灯前停止"""
    if traffic_light is None:
        return False

    light_state = traffic_light.get_state()
    if light_state == carla.TrafficLightState.Green:
        return False

    # 计算车辆到停止线的距离
    vehicle_loc = vehicle.get_location()
    stop_waypoints = traffic_light.get_stop_waypoints()
    if not stop_waypoints:
        return False

    stop_loc = stop_waypoints[0].transform.location
    distance = vehicle_loc.distance(stop_loc)

    # 如果距离停止线小于阈值，必须停止
    if distance < stop_margin:
        return True

    # 红灯/黄灯且即将到达停止线
    if light_state in [carla.TrafficLightState.Red,
                       carla.TrafficLightState.Yellow]:
        return distance < 15.0  # 15米内需要减速

    return False
```

### 43.3.3 多路口场景

车辆可能同时受到多个交通灯影响（多车道、大路口）。处理逻辑：

```python
def get_relevant_traffic_light(world, vehicle):
```

## 43.4 Traffic Manager

### 43.4.1 CARLA 内置交通管理

**Traffic Manager (TM)** 是 CARLA 提供的自动驾驶交通流管理模块，可以控制多辆 AI 车辆的行为。TM 使得仿真环境中的交通流更加真实。

```python
client = carla.Client('localhost', 2000)
world = client.get_world()

# 创建 Traffic Manager 实例
traffic_manager = client.get_trafficmanager(8000)  # 端口参数

# 将车辆交给 TM 控制
vehicle.set_autopilot(True, traffic_manager.get_port())
```

### 43.4.2 核心参数配置

| 参数 | 方法 | 范围 | 说明 |
|------|------|------|------|
| 车速 | `set_desired_speed(vehicle, kmh)` | [0, 200] | 目标车速 (km/h) |
| 跟车距离 | `set_distance_to_leading_vehicle(vehicle, dist)` | [0.5, 100] | 与前车的距离 (m) |
| 闯灯概率 | `set_ignore_traffic_light_percentage(vehicle, pct)` | [0, 100] | 忽略红绿灯的百分比 |
| 变道偏好 | `set_lane_change_behavior(vehicle, mode)` | 0/1/2 | 0:无变道,1:左,2:右 |
| 限速忽略 | `set_ignore_signs_percentage(vehicle, pct)` | [0, 100] | 忽略限速标志 |
| 强行变道 | `set_force_lane_change(vehicle, enable)` | True/False | 强制变道 |

### 43.4.3 配置示例

```python
def configure_aggressive_driver(traffic_manager, vehicle):
    """配置激进驾驶风格"""
    traffic_manager.set_desired_speed(vehicle, 80.0)
    traffic_manager.set_distance_to_leading_vehicle(vehicle, 2.0)
    traffic_manager.set_ignore_traffic_light_percentage(vehicle, 20.0)
    traffic_manager.set_ignore_signs_percentage(vehicle, 10.0)
    traffic_manager.set_lane_change_behavior(vehicle, 2)  # 右道优先

def configure_conservative_driver(traffic_manager, vehicle):
    """配置保守驾驶风格"""
    traffic_manager.set_desired_speed(vehicle, 50.0)
    traffic_manager.set_distance_to_leading_vehicle(vehicle, 8.0)
    traffic_manager.set_ignore_traffic_light_percentage(vehicle, 0.0)
    traffic_manager.set_ignore_signs_percentage(vehicle, 0.0)
    traffic_manager.set_lane_change_behavior(vehicle, 1)  # 左道优先
```

### 43.5.3 自定义场景：行人横穿

```python
import py_trees
from srunner.scenariomanager.atomic_scenario_behavior import *
from srunner.scenariomanager.atomic_scenario_criteria import *
from srunner.scenarios.basic_scenario import BasicScenario

class PedestrianCrossing(BasicScenario):
    """自定义场景：行人突然横穿马路"""

    def __init__(self, world, ego_vehicles, config, ...):
        super().__init__(
            name="PedestrianCrossing",
            ego_vehicles=ego_vehicles,
            config=config,
            world=world,
            debug_mode=False,
            terminate_on_failure=True,
        )

    def _initialize_actors(self, config):
        """生成行人和设置初始位置"""
        pedestrian_loc = self._get_spawn_point()
        pedestrian_blueprint = (
            self._world.get_blueprint_library()
            .find("walker.pedestrian.*")
        )
        self._pedestrian = self._world.spawn_actor(
            pedestrian_blueprint, pedestrian_loc
        )
        self.other_actors.append(self._pedestrian)

    def _create_behavior(self):
        """定义场景行为树"""
        root = py_trees.composites.Sequence("PedestrianBehavior")
        # 等待自车接近
        approach = WaypointReached(
            self.ego_vehicles[0], self._trigger_point, 5.0
        )
        # 行人开始横穿
        cross = CrossPedestrian(self._pedestrian, self._target_point)
        root.add_child(approach)
        root.add_child(cross)
        return root

    def _create_test_criteria(self):
        """定义评估标准"""
        collision_criterion = CollisionTest(self.ego_vehicles[0])
        return [collision_criterion]
```

```python
class CutInScenario(BasicScenario):
    """前车切入本车车道"""

    def _create_behavior(self):
        root = py_trees.composites.Sequence("CutInBehavior")
        # 等待两车接近
        wait = DriveDistance(self._cutting_vehicle, 30.0)
        # 切入动作
        cut_in = ChangeLane(
            self._cutting_vehicle,
            direction="left",
            target_lane_id=self._target_lane
        )
        # 减速
        brake = BrakeVehicle(self._cutting_vehicle, 0.7)
        root.add_child(wait)
        root.add_child(cut_in)
        root.add_child(brake)
        return root
```

## 总结

本章核心要点：

1. **行为决策**是自动驾驶分层架构的中间层，连接任务规划与运动规划。
2. **有限状态机 (FSM)** 是实现行为决策的经典方法，状态定义清晰，转移逻辑直观。
3. **交通灯响应**需要结合停止线判断和灯色识别，CARLA 提供了完整的 API 支持。
4. **Traffic Manager** 适合控制背景交通流，可通过参数调节驾驶风格。
5. **Scenario Runner** 是场景测试框架，支持内置场景和自定义场景。

下一章将在此基础上进一步讲解运动规划与轨迹生成算法。

### 1. 分层决策与 FSM 的国际课程范式

多伦多大学在 Coursera 的自动驾驶专项课程（其中「Motion Planning for Self-Driving Cars」模块）与本章 43.1.1 的分层架构完全对应：任务规划（mission，A\* 全局路径）→ 行为规划（behavior，FSM 生成局部目标）→ 运动规划（motion，轨迹生成与跟踪），课程作业要求用有限状态机实现「车道保持 → 跟车 → 停车 → 停车让行」的转移逻辑，并强调两条工程纪律：每个状态必须显式声明进入/退出条件，转移条件要「非重叠、可穷举」，否则 FSM 会出现不可复现的抖动——这正是 43.2.3 状态转移表在工程上的意义。课程还对比了行为树的优劣：状态多时可读性更好，但需要额外处理「回退（fallback）节点」优先级，可作为 43.2.4 FSM 实现要点的进阶阅读。

### 2. CARLA 交通灯 API 的官方细节

CARLA 官方文档《Traffic Lights》章节给出了与 43.3.1 一致的 API 全集：`traffic_light.get_state()` 返回红/黄/绿枚举，`get_affected_lane_waypoints()` 返回该灯管辖的停止线 waypoint 列表（官方强调这是「判断是否受控于该灯」的推荐方式），`get_green_time()`/`get_elapsed_time()` 则用于超时预测。官方还提醒两个易错点：其一，CARLA 中交通灯对车辆的影响判定是基于距离与车道归属的，自动驾驶控制必须自行查询并遵守灯色（模拟器不会替你刹车）；其二，`world.get_actors()` 过滤 `traffic.traffic_light` 后再按 `get_opendrive_id()` 与地图对齐，是跨场景复用识别结果的标准做法——与 43.3.2 停止线判断的实现思路一致。

### 3. Traffic Manager 官方架构：阶段流水线与混合物理模式

CARLA 官方文档把 Traffic Manager 描述为「CARLA 内置的自动驾驶后台」：内部按定位、碰撞检测、交通灯处理、运动学四个阶段（stages）流水线运行，每个 actor 独立计算，最终以控制指令驱动车辆——本章 43.4.1 的描述即此架构的概括。官方参数文档与 43.4.2 一一对应：`distance_to_leading_vehicle`、`percent_speed_difference`、`auto_lane_change`、`percentage_speed_difference` 等均通过 `set_global`/`set_percentage` 两级 API 配置，且官方建议大批量背景车辆开启「混合物理模式（hybrid physics mode）」：仅对 ego 附近车辆启用全物理仿真、远处车辆用运动学简化，以把 CPU 开销压到可用水平。官方还说明 TM 与外部控制器可共存，但同一车辆不能同时被 TM 与 FSM 接管——正是 43.4.4 讨论的边界条件。

### 4. Scenario Runner 与 OpenSCENARIO：场景测试的官方框架

CARLA 官方的 scenario_runner 仓库定义了与 43.5 一致的三层结构：场景（scenario，含行为树与成功/失败判据）→ 带判据的条件序列 → 具体 actor 行为；官方 `srunner` 示例（FollowLeadingVehicle、TrafficLightScenario 等）正是 43.5.2 内置场景的来源。官方文档还支持 ASAM OpenSCENARIO 1.x 标准（`--openscenario` 参数直接运行 `.xosc` 文件），把「行人横穿」「前车切入」这类自定义场景写成跨仿真器可移植的标准 XML——这是 43.5.3/43.5.4 自定义场景的进阶路线。工程实践上，官方建议把场景库纳入回归测试（CI 中每次跑一遍全量场景），让「交通规则遵守率」成为可持续度量的指标，而非一次性演示。
