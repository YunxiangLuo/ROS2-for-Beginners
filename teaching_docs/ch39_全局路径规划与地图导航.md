# 第39章 全局路径规划与地图导航

## 39.1 OpenDRIVE 地图格式

### 39.1.1 HD Map 概念

高精度地图（HD Map）是自动驾驶系统的核心基础，其精度可达厘米级，包含道路拓扑、车道边界、交通标志、坡度曲率等丰富信息。与传统导航地图不同，HD Map 不仅服务于人类驾驶员，更主要面向机器决策与规划系统。

HD Map 关键特征：

| 特征 | 描述 | 传统地图对比 |
|------|------|-------------|
| 精度 | 10-20cm 误差 | 5-10m 误差 |
| 车道级 | 每条车道独立建模 | 道路级聚合 |
| 语义信息 | 停止线、限速、转向规则 | 仅有路名 |
| 高程信息 | 道路横坡/纵坡/超高 | 通常无 |
| 更新频率 | 云端实时更新 | 季度更新 |

### 39.1.2 道路/车道/连接描述

OpenDRIVE 使用 XML 格式描述道路网络，核心概念有三个：**道路（Road）**由参考线（Reference Line）定义，包含若干车道段；**车道（Lane）**则是每条道路被划分为中心线两侧的车道，左正右负编号；**连接（Junction/Connection）**描述不同道路之间的拓扑关系。

**OpenDRIVE XML 示例：**

```xml
<OpenDRIVE>
  <header revMajor="1" revMinor="4" name="CARLA_Town03"/>
  <road name="Road_0" length="256.78" id="0" junction="-1">
    <planView>
      <geometry s="0.0" x="12.34" y="56.78" hdg="0.523" length="256.78">
        <line/>
      </geometry>
    </planView>
    <elevationProfile>
      <elevation s="0.0" a="0.0" b="0.0" c="0.0" d="0.0"/>
    </elevationProfile>
    <lateralProfile/>
    <lanes>
      <laneOffset s="0.0" a="3.5" b="0.0" c="0.0" d="0.0"/>
      <laneSection s="0.0">
        <left>
          <lane id="1" type="driving" level="0">
            <width s="0.0" a="3.5" b="0.0" c="0.0" d="0.0"/>
            <roadMark s="0.0" type="solid" weight="standard" color="white"/>
          </lane>
        </left>
        <center>
          <lane id="0" type="none" level="0">
            <roadMark s="0.0" type="broken" weight="standard" color="white"/>
          </lane>
        </center>
        <right>
          <lane id="-1" type="driving" level="0">
            <width s="0.0" a="3.5" b="0.0" c="0.0" d="0.0"/>
            <roadMark s="0.0" type="solid" weight="standard" color="white"/>
          </lane>
          <lane id="-2" type="sidewalk" level="0">
            <width s="0.0" a="2.0" b="0.0" c="0.0" d="0.0"/>
          </lane>
        </right>
      </laneSection>
    </lanes>
  </road>
</OpenDRIVE>
```

### 39.1.3 CARLA OpenDRIVE 地图

CARLA 模拟器内置的每个城镇（Town01~Town12）均包含对应的 OpenDRIVE 描述文件。通过 CARLA Python API 可直接获取：

```python
# 获取 CARLA 地图的 OpenDRIVE 字符串
world = client.get_world()
opendrive_str = world.get_map().to_opendrive()
with open("town03.xodr", "w") as f:
    f.write(opendrive_str)
```

CARLA 在 OpenDRIVE 基础上额外扩展了 `carla_` 前缀的自定义属性，用于描述交通灯、生成点等仿真特定信息。

### 39.1.4 官方要点——OpenDRIVE 官方规范：参考线、车道与几何组合

ASAM OpenDRIVE 官方规范把一条道路（road）定义为「参考线（reference line）+ 车道集合」：参考线由圆弧（arc）、样条（spiral/clothoid）等基础几何分段拼接，车道（lane）相对参考线用宽度与横向偏移描述，车道之间再用「车道连接」（laneLink）与「前驱/后继」（predecessor/successor）构成路网拓扑——与本章 39.1.2 的道路/车道/连接描述一一对应。官方文档对两处细节的强调值得注意：多车道道路允许多条参考线（`@allowMultipleLanesPerRoad`），且车道连接必须满足「几何连续性」否则 `Lanelet2` 转换会报错——这解释了 39.2.2 中 CARLA 导出地图的常见坑：OpenDRIVE 里的惯性惯性坐标与 CARLA 的米制世界坐标偏差源于参考线原点定义，读取时需 `xodr` 解析后按原点平移。

## 39.2 全局路径规划算法

### 39.2.1 Dijkstra vs A\* 算法

全局路径规划在已知路网中搜索从起点到终点的最优路径。Dijkstra 和 A\* 是最经典的两个算法。

| 对比项 | Dijkstra | A\* |
|--------|----------|-----|
| 搜索策略 | 广度优先均匀扩展 | 启发式导向搜索 |
| 启发函数 | 无 (g(n) only) | f(n) = g(n) + h(n) |
| 保证最优 | 是 | 是 (h(n) 需可采纳) |
| 搜索效率 | 慢（全向扩展） | 快（目标导向） |
| 内存消耗 | 大 | 相对小 |
| 适用场景 | 权重未知、负权边 | 路网已知、曼哈顿距离 |

### 39.2.2 启发函数设计

A\* 算法的核心在于启发函数 h(n)，常见选择有三种：**欧几里得距离** `h(n) = sqrt((xn - xg)^2 + (yn - yg)^2)` 可采纳，适合自由空间；**曼哈顿距离** `h(n) = |xn - xg| + |yn - yg|` 可采纳，适合网格化路网；**对角线距离** `h(n) = max(|dx|, |dy|)` 可采纳，允许 8 方向移动。

若 h(n) 过估，A\* 可能失去最优性；若 h(n)=0，退化为 Dijkstra。

### 39.2.3 搜索过程对比

```
Dijkstra 搜索:                     A* 搜索:
                                   
    S - * - * - * - *              S - * - * - * - G
    |   |   |   |   |              |   |   |   |   |
    * - * - * - * - *              * - * - * - G
    |   |   |   |   |              |   |   |   |
    * - * - * - * - *              * - * - G
    |   |   |   |   |              |   |   |
    * - * - * - * - G              * - * - G
    |   |   |   |   |
    * - * - * - * - *

S=起点  G=目标  *=已扩展节点
Dijkstra 均匀向外扩散        A* 沿目标方向定向扩展
```

A\* 算法伪代码：

```
function A_Star(start, goal, h_func):
    open_set = PriorityQueue()
    open_set.add(start, f_score=0)
    came_from = empty_map
    g_score[start] = 0

    while open_set not empty:
        current = open_set.pop()
        if current == goal:
            return reconstruct_path(came_from, current)

        for neighbor in neighbors(current):
            tentative_g = g_score[current] + dist(current, neighbor)
            if tentative_g < g_score[neighbor]:
                came_from[neighbor] = current
                g_score[neighbor] = tentative_g
                f_score[neighbor] = g_score[neighbor] + h_func(neighbor, goal)
                open_set.add_or_update(neighbor, priority=f_score[neighbor])

    return empty  # 无可行路径
```

### 39.2.4 官方要点——Dijkstra 与 A\*：两篇经典文献与数据结构教学

Dijkstra 的 1959 年论文 `A Note on Two Problems in Connexion with Graphs` 首次给出非负权图最短路径算法；A\* 则出自 Hart–Nilsson–Raphael 1968 年的 `A Formal Basis for the Heuristic Determination of Minimum Cost Paths`——本节 39.2 的对比（启发函数、可采纳性与遍历开销）正是这两篇文献的通行教学结论。国际算法教材（如 CLRS《算法导论》）的规范性表述：Dijkstra 用「优先队列 + 已确定集合」实现，每次弹出最小距离节点并松弛邻边，时间复杂度 O(E·log V)；A\* 在 Dijkstra 的启发函数 h(n) 可采纳（admissible，即低估真实代价）时保证最优。教材同时指出：实际工程中二者都可用二叉堆实现，二叉堆无法高效减小键时才换斐波那契堆——对教学代码而言直接用 `heapq` + 惰性删除即可。

## 39.3 道路网络与 Waypoint

### 39.3.1 CARLA Waypoint API

CARLA 的 Waypoint 是道路上离散采样点，包含精确的位置和朝向信息。每个 Waypoint 位于某条车道的中心线上。

```python
# 基本 Waypoint 操作
map = world.get_map()

# 获取生成点附近的 waypoint
spawn_point = world.get_spawn_points()[0]
waypoint = map.get_waypoint(spawn_point.location)

# 获取前方/后方 waypoint
next_wp = waypoint.next(2.0)    # 前方 2m 处 waypoint 列表
prev_wp = waypoint.previous(2.0) # 后方 2m 处 waypoint 列表

# 车道变化
left_wp = waypoint.get_left_lane()
right_wp = waypoint.get_right_lane()

# 路口信息
is_junction = waypoint.is_junction
junction_id = waypoint.junction_id
```

### 39.3.2 车道中心线生成

Waypoint 对象天然位于车道中心线，可用来生成路径：

```
Waypoint 导航示意图:

          ╔══════════════════════════════════╗
          ║   Lane -1 (左车道)               ║
          ║   ┌─────┬─────┬─────┬─────┐     ║
          ║   │ WP0 │ WP1 │ WP2 │ WP3 │ ... ║  ← 左车道中心线 waypoint
          ║   └─────┴─────┴─────┴─────┘     ║
  中心线  ════════════════════════════════════
          ║   ┌─────┬─────┬─────┬─────┐     ║
          ║   │ WP0 │ WP1 │ WP2 │ WP3 │ ... ║  ← 右车道中心线 waypoint
          ║   └─────┴─────┴─────┴─────┘     ║
          ║   Lane -2 (右车道)               ║
          ╚══════════════════════════════════╝
```

### 39.3.3 路径生成

通过 Waypoint 的 `next()` 方法迭代，可生成连续路径：

```python
def generate_path(map, start_location, distance=2.0, max_steps=500):
    waypoint = map.get_waypoint(start_location)
    path = [waypoint]

    for _ in range(max_steps):
        next_wps = waypoint.next(distance)
        if not next_wps:
            break

        # 多岔路时选择最接近当前朝向的 waypoint
        next_wp = min(next_wps,
            key=lambda wp: abs(wp.transform.rotation.yaw - waypoint.transform.rotation.yaw))
        path.append(next_wp)
        waypoint = next_wp

    return path
```

### 39.3.4 官方要点——Waypoint API 的官方用法：从生成到采样

CARLA 官方文档《Waypoints》章节给出与 39.3.1 一致的标准流程：`map.generate_waypoints(distance)` 生成路网离散点、`map.get_waypoint(location)` 按碰撞查询最近车道点（可用 `project_to_road` 投影）、`waypoint.next(d)` 沿车道前进采样，「下一批」默认取紧邻车道所有分支（左右换道点），因此官方教程强调取 `.next(2.0)[0]` 才得到当前车道直行点——这是 39.3.3 路径生成中「车道中心线」debug 绘制时最容易出现的多帧漂移问题根源（若取了分支点，绘制出的中心线会突然横跳）。官方还提示：`is_intersection` / `lane_change` 字段用于判断红绿灯与换道点，与 39.3.2 的转向分类对应。

## 39.4 Lanelet2 地图

### 39.4.1 Lanelet / LaneletMap 概念

Lanelet2 是 Autoware 等开源自动驾驶系统采用的高精地图格式，将道路划分为多个 Lanelet（车道片段）。

**核心数据结构：**

Lanelet2 的核心数据结构有四类：**Lanelet** 包含左右边界线（Linestring）的可通行区域，附有属性（限速、转向等）；**Linestring** 是由 3D 点序列组成的线，标记车道边界、停止线等；**RegulatoryElement** 是交通规则元素（红灯、限速牌、让行标志）；**LaneletMap** 是所有元素的集合容器。

```
Lanelet 结构示意图:

           Linestring 左边界
        ┌─────────────────────┐
        │  Lanelet 1          │  ← 限速 60km/h, 直行
        │  (左转车道)          │
        ├─────────────────────┤
        │  Lanelet 2          │  ← 限速 60km/h, 直行
        │  (直行车道)          │
        ├─────────────────────┤
        │  Lanelet 3          │  ← 限速 60km/h, 右转
        │  (右转车道)          │
        └─────────────────────┘
           Linestring 右边界
```

### 39.4.2 OpenDRIVE 到 Lanelet2 的转换

Lanelet2 与 OpenDRIVE 可以互相转换。Autoware 使用 `lanelet2_io` 工具加载 `.osm` 或 `.xodr` 文件：

```cpp
// C++: 加载 Lanelet2 地图
#include <lanelet2_io/io.h>

lanelet::LaneletMap::Ptr map = lanelet::load("map.osm", "autoware.orbis");
for (const auto& lanelet : map->laneletLayer) {
    double speed_limit = lanelet.attributeOr("speed_limit", 60.0);
    // 获取左右边界
    auto left_bound = lanelet.leftBound();
    auto right_bound = lanelet.rightBound();
}
```

### 39.4.3 Autoware 兼容格式

Autoware 采用 OSM（OpenStreetMap XML）格式存储 Lanelet2 地图，示例如下：

```xml
<osm version="0.6">
  <node id="1001" lat="35.681236" lon="139.767125"/>
  <node id="1002" lat="35.681240" lon="139.767200"/>
  <node id="1003" lat="35.681250" lon="139.767300"/>

  <way id="2001">
    <nd ref="1001"/>
    <nd ref="1002"/>
    <nd ref="1003"/>
    <tag k="type" v="line_thin"/>
    <tag k="subtype" v="solid"/>
  </way>

  <relation id="3001">
    <member type="way" ref="2001" role="left"/>
    <member type="way" ref="2002" role="right"/>
    <tag k="type" v="lanelet"/>
    <tag k="subtype" v="road"/>
    <tag k="speed_limit" v="60"/>
    <tag k="one_way" v="yes"/>
  </relation>
</osm>
```

Lanelet2 支持的地图属性包括：`speed_limit` 限速 (km/h)、`one_way` 单行道、`turn_direction` 转向方向 (straight/left/right)、`lane_type` 车道类型 (driving/bike/walkthrough)。

### 39.4.4 官方要点——Lanelet2 与 Autoware 官方生态：从地图到运行栈

Lanelet2 官方文档把地图拆为三种元素：车道（lanelets）、交通灯与路权元素（regulatory elements）、站点/区域（areas），并强调其「语义保持」设计——转换（如从 OpenDRIVE）只保证几何不保证语义，这是 39.4.2 转换章节的核心难点。Autoware 官方文档则展示了 Lanelet2 的完整消费链：`autoware_auto_msgs` 的地图消息 + `lanelet2_map_provider` 发布 → `behavior_planner` 用 Lanelet2 选道 → 轨迹规划器生成参考线——对应 39.4.3 的 Autoware 兼容格式。官方还提供 `lanelet2_examples` 与 `lanelet2_python` 教程（绘制、查询、导出），建议读者把本章 CARLA 导出的 `.osm` 文件用 `lanelet2_python` 可视化一遍，直观理解「车道中心线 + 路权元素」的表示代价。
