## 42.1 目标检测概述

### 42.1.1 2D与3D目标检测

目标检测是自动驾驶感知的核心任务，分为2D检测（图像平面）和3D检测（空间位置）。

| 维度 | 输入 | 输出 | 典型算法 | 优点 | 缺点 |
|:----:|:----:|:----:|:--------:|:----:|:----:|
| 2D检测 | RGB图像 | bbox + 类别 | YOLO, Faster R-CNN | 速度快，数据集丰富 | 缺少深度信息 |
| 3D检测 | LiDAR/立体相机 | 3D bbox + 类别 | PointPillars, VoxelNet | 完整空间信息 | 点云稀疏，计算量大 |

### 42.1.2 精度评价指标

**IoU（Intersection over Union）**：预测框与真值框的交并比。

```
IoU = Area(Intersection) / Area(Union)

      ┌────┐
 ┌────┤GT  │
 │Pred│░░░░│
 └────┘░░░░│
      └────┘
   IoU = ░░ / (□ + □ - ░░)
```

**mAP（mean Average Precision）**：对所有类别求AP的平均值。具体而言，AP为PR曲线下面积；mAP@0.5指IoU阈值为0.5时的mAP；mAP@0.5:0.95指IoU从0.5到0.95（步长0.05）取平均后的mAP。

### 42.1.3 目标检测流程

```
输入图像 → 特征提取(Backbone) → 特征金字塔(Neck) → 检测头(Head) → 后处理(NMS)
   │             │                     │                │              │
   │        ResNet/ViT/CSP        FPN/PAN         分类+回归     过滤重叠框
   └─────────────┴─────────────────────┴────────────────┴──────────────┘
```

### 42.1.4 官方要点——检测精度的国际基准：KITTI 官方指标

> 本节内容综合翻译自 Ultralytics 官方文档（YOLOv8）、KITTI 官方基准说明、PCL 官方文档（聚类模块）与 SORT 官方论文及代码库（Bewley 等，2016），DBSCAN 部分参考 Ester 等（1996）原始论文的通行讲法。原文均为英文，此处为中文编译，供课后巩固与进阶阅读。

本章 42.1.2 的精度评价（IoU、AP）对应国际标准基准 KITTI 的官方评测协议：2D 检测以 IoU≥0.7（车辆）/0.5（行人、骑行者）判正样本，AP 按 easy/moderate/hard 三档（按遮挡与截断程度划分）分别报告，官方排名以 moderate 档为准；3D 检测则把 IoU 抬升到鸟瞰框层面（BEV AP）。KITTI 官方开发包 `kitti-object-eval-python` 的实现被后续 nuScenes、Waymo 基准沿用，其「按置信度排序后计算 PR 曲线下的 AP（40 点插值）」是本章公式与实验数据的标准来源。建议读者把 YOLO 输出转为 KITTI 标签格式后在官方脚本上跑一遍，直观理解「模型 mAP 与工程可用性」的差距。

## 42.2 YOLO目标检测

### 42.2.1 YOLO原理

YOLO（You Only Look Once）是单阶段目标检测算法，将检测视为回归问题，一次性预测所有边界框和类别概率。

**核心思想**：将图像划分为S×S网格，每个网格负责预测中心落在该网格内的目标。

```
YOLO网络结构:
┌────────────┐    ┌────────────┐    ┌───────────┐    ┌──────────────┐
│ Backbone   │ →  │ Neck       │ →  │ Head      │ →  │ Post-process │
│ (CSPDarknet│    │ (PAN-FPN)  │    │ (Decoupled│    │ (NMS)        │
│  /C2f)     │    │            │    │  Head)    │    │              │
└────────────┘    └────────────┘    └───────────┘    └──────────────┘
     ↓                  ↓                 ↓
 多尺度特征       特征融合         分类分支
 (P3/P4/P5)     跨尺度传递       回归分支
                                    
输出张量: [batch, 4+1+C, N_anchors]
  • 4: bbox坐标 (tx, ty, tw, th)
  • 1: 目标置信度
  • C: 类别数 (COCO: 80)
  • N_anchors: 每个网格的锚框数
```

**单阶段vs双阶段**：

| 特性 | 单阶段 (YOLO) | 双阶段 (Faster R-CNN) |
|:----:|:-------------:|:--------------------:|
| 速度 | 快（实时） | 较慢 |
| 精度 | 高（v8+已接近） | 更高 |
| 流程 | 一步回归 | 先提候选框再分类 |
| 适用 | 实时自动驾驶 | 精度优先场景 |

### 42.2.2 YOLOv8网络结构

YOLOv8的核心改进：

```
YOLOv8 Architecture Detail:

Backbone (CSPDarknet):
  Input(3×640×640)
  → Conv k3s2 (64)
  → C2f (128) ←── Cross Stage Partial with 2 convolutions
  → Conv k3s2 (128)
  → C2f (256)
  → Conv k3s2 (256)
  → C2f (512)       ──→ P4 (1/16)
  → Conv k3s2 (512)
  → C2f (512) × 3   ──→ P5 (1/32)   ←── SPPF

Neck (PAN-FPN):
  P5 → ConvUp → concat(P4) → C2f → P5'
  P4 → ConvUp → concat(P3) → C2f → P4'
  P4' → Conv → concat(P5') → C2f → P5''

Head (Decoupled):
  每个尺度 → 2个Conv分支 → 分类输出 + 回归输出 → DFL + IoU Loss
```

### 42.2.4 官方要点——YOLOv8 官方文档：模型家族与推理 API

Ultralytics 官方文档对 YOLOv8 给出与本章 42.2.2 一致的结构说明：backbone 用 C2f 模块替代 YOLOv5 的 C3、检测头解耦为「分类 + 回归」两条分支并采用 anchor-free 设计；官方同时提供从 `yolov8n`（nano）到 `yolov8x` 的模型家族，官方基准表以 mAP 与推理延迟双维度给出选型依据——嵌入式平台（Jetson）普遍选 n/s 档，正是 42.2.1 单阶段实时检测的官方实现。推理 API 方面，官方 `model.predict(source, conf=..., iou=...)` 直接返回检测框张量，`model.track` 内置 ByteTrack 级别的跟踪逻辑（可指定 `tracker="bytetrack.yaml"`），与 42.2.3 的 ROS 2 集成接口对接时只需把 `results.boxes` 转为 `vision_msgs/Detection2DArray`。官方文档还提醒：训练与推理的输入尺寸（640）与归一化要保持一致，否则 mAP 会无故掉点。

## 42.3 LiDAR点云聚类

### 42.3.1 点云预处理

原始LiDAR点云数据量大且包含噪声，需要进行预处理。

**体素滤波（Voxel Filter）**：将空间划分为三维体素网格，每个体素内保留一个代表点（重心或中心点）。

```
体素滤波示意图:
                    ┌───┬───┬───┐
                    │ · │ · │   │  ← 每个体素内取平均
  原始点云: ····  → ├───┼───┼───┤
                    │   │ · │ · │
                    └───┴───┴───┘
  稠密点云            稀疏化点云（体素尺寸=0.1m）
```

**直通滤波（PassThrough Filter）**：在指定坐标轴方向截取范围区间内的点。

```python
# 直通滤波：保留前方0~50m范围
x_min, x_max = 0.0, 50.0   # X轴前方
y_min, y_max = -20.0, 20.0 # Y轴左右
z_min, z_max = -2.0, 3.0   # Z轴高度

mask = (points[:, 0] >= x_min) & (points[:, 0] <= x_max) & \
       (points[:, 1] >= y_min) & (points[:, 1] <= y_max) & \
       (points[:, 2] >= z_min) & (points[:, 2] <= z_max)
filtered = points[mask]
```

**半径滤波（Radius Outlier Removal）**：对每个点，统计半径R内邻点数量，少于阈值则视为离群点移除。

### 42.3.2 DBSCAN聚类算法

DBSCAN（Density-Based Spatial Clustering of Applications with Noise）是一种基于密度的聚类算法，不需要预先指定聚类数量。

```
DBSCAN算法参数:
  • eps (ε): 邻域半径
  • minPts: 核心点的最小邻域点数

算法流程:
  1. 对每个点，计算ε邻域内的点数
  2. 若点数 ≥ minPts，标记为核心点
  3. 核心点之间密度可达 → 同一簇
  4. 非核心点但落在核心点邻域内 → 边界点
  5. 其他 → 噪声点

示意图:
  噪声点·   ·边界点   ·核心点   ··核心点的ε邻域
    ·    ╭──────╮
     ·· ╱ ····· ╲··
       │ ·◎····· │
     ·· ╲ ··◎·· ╱··
        ╰──────╯
   ○ = 核心点  ◎ = 边界点  · = 噪声点

DBSCAN vs K-Means:
  • DBSCAN: 自动发现簇数，任意形状，抗噪声
  • K-Means: 需指定K，凸形簇，对噪声敏感
```

### 42.3.3 欧式聚类

欧式聚类是DBSCAN在三维空间中的特例，基于点之间的欧氏距离进行聚类。

```python
def euclidean_clustering(points, cluster_tolerance=0.5, min_cluster_size=10, max_cluster_size=10000):
    """欧式聚类实现"""
    from sklearn.cluster import DBSCAN

    clustering = DBSCAN(
        eps=cluster_tolerance,
        min_samples=min_cluster_size,
        metric='euclidean',
        n_jobs=-1
    ).fit(points)

    labels = clustering.labels_
    n_clusters = len(set(labels)) - (1 if -1 in labels else 0)

    clusters = []
    for label in range(n_clusters):
        mask = labels == label
        cluster_points = points[mask]
        if min_cluster_size <= len(cluster_points) <= max_cluster_size:
            clusters.append(cluster_points)

    return clusters, labels
```

**聚类后障碍物表示**：

```
每个聚类 → 障碍物:
  ┌──────────────────────┐
  │ 中心点 (centroid)    │ ← 聚类点云均值
  │ 3D边界框             │ ← 最小/最大坐标
  │ 点云数量             │ ← 体积/密集度
  │ 运动状态 (动态/静态) │ ← 多帧比较
  └──────────────────────┘
```

### 42.3.4 官方要点——DBSCAN 与欧式聚类的官方实现要点

点云聚类的两条实现路线在官方文档中都有明确说法：DBSCAN 原始论文（Ester 等，1996）定义了 eps/minPts 与「核心点/边界点/噪声点」概念，sklearn 官方文档警告其复杂度 O(n²)（可用树索引优化），因此大点云常用「降采样后聚类」；PCL 官方文档的 `EuclideanClusterExtraction` 则给出工程参数直觉——`cluster_tolerance`（聚类容差）应接近传感器点距（常用 0.5–1.0 m，与 42.3.2 的说法一致），过小会把同一车体拆成多个簇、过大把行人与树木连成一片。PCL 官方示例还演示了先用 `VoxelGrid` 降采样、`CropBox`/`PassThrough` 裁剪 ROI 再聚类的标准管线，与 42.3.1 点云预处理顺序完全对应。

## 42.4 多目标跟踪

### 42.4.1 卡尔曼滤波跟踪

卡尔曼滤波通过预测-更新循环对目标状态进行最优估计。

```
状态向量: x = [cx, cy, cz, vx, vy, vz, w, h, l]
            位置     速度     尺寸

预测步骤:
  x̂ₖ|ₖ₋₁ = F·x̂ₖ₋₁|ₖ₋₁ + B·uₖ          # 状态预测
  Pₖ|ₖ₋₁ = F·Pₖ₋₁|ₖ₋₁·Fᵀ + Q          # 协方差预测

更新步骤:
  Kₖ = Pₖ|ₖ₋₁·Hᵀ·(H·Pₖ|ₖ₋₁·Hᵀ + R)⁻¹  # 卡尔曼增益
  x̂ₖ|ₖ = x̂ₖ|ₖ₋₁ + Kₖ·(zₖ - H·x̂ₖ|ₖ₋₁)  # 状态更新
  Pₖ|ₖ = (I - Kₖ·H)·Pₖ|ₖ₋₁             # 协方差更新

F: 状态转移矩阵    Q: 过程噪声协方差
H: 观测矩阵        R: 观测噪声协方差
```

**跟踪流水线**：

```
帧1: 检测 → 初始化跟踪器(分配ID=1,2,...)
帧2: 检测 → 预测(卡尔曼预测) → 匹配(匈牙利算法) → 更新(卡尔曼更新)
帧3: 检测 → 预测 → 匹配 → 更新
  ...
帧N: 丢失目标 → 计数值++ → 超过阈值 → 删除跟踪器
```

### 42.4.2 匈牙利匹配

匈牙利算法解决检测与跟踪目标之间的最优分配问题。

```
代价矩阵构建:
        检测 D₁  D₂  D₃  ...  Dₘ
跟踪 T₁  [d₁₁  d₁₂  d₁₃  ...  d₁ₘ]
    T₂   [d₂₁  d₂₂  d₂₃  ...  d₂ₘ]
    T₃   [d₃₁  d₃₂  d₃₃  ...  d₃ₘ]
    ...  [ ...  ...  ...  ...  ...]
    Tₙ   [dₙ₁  dₙ₂  dₙ₃  ...  dₙₘ]

dᵢⱼ = IoU(跟踪Tᵢ的预测框, 检测Dⱼ的检测框)  ← 取负值作为代价

匈牙利算法步骤:
  1. 每行减去最小值
  2. 每列减去最小值
  3. 用最少直线覆盖所有零元素
  4. 若直线数=维度，找到最优匹配
  5. 否则，调整矩阵并重复步骤3
```

**匹配策略**：

| 场景 | 处理 |
|:----:|:----:|
| 检测匹配到跟踪 | 更新跟踪器状态，重置丢失计数 |
| 检测无匹配 | 创建新跟踪器，分配新ID |
| 跟踪无匹配 | 增加丢失计数，若超阈值则删除 |
| IoU < 阈值 | 视为无效匹配，强制不匹配 |

### 42.4.3 ID分配与管理

每个目标在其生命周期内保持唯一ID：

```python
class TrackObject:
    """单个跟踪目标"""
    def __init__(self, obj_id, detection):
        self.id = obj_id
        self.class_name = detection.class_name
        self.confidence = detection.confidence

        # 卡尔曼滤波器
        self.kf = KalmanFilter(dim_x=9, dim_z=6)
        self.kf.x = self.init_state(detection)

        self.lost_count = 0     # 丢失帧计数
        self.hit_count = 1      # 命中帧计数
        self.max_lost = 10      # 最大容忍丢失帧数
        self.is_confirmed = False

    def predict(self):
        self.kf.predict()
        self.lost_count += 1
        return self.get_state()

    def update(self, detection):
        self.kf.update(self.measurement(detection))
        self.lost_count = 0
        self.hit_count += 1
        self.is_confirmed = self.hit_count > 3
```

**ID分配规则**：新检测无匹配时分配自增新ID；连续命中3帧以上则确认为稳定跟踪；丢失超过阈值则释放ID；已释放的ID不会立即重用，以避免ID跳变。

### 42.4.5 官方要点——SORT 与匈牙利算法：多目标跟踪的教科书组合

本章 42.4 的「卡尔曼滤波 + 匈牙利匹配」框架出自 Bewley 等 2016 年的 SORT 论文（Simple Online and Realtime Tracking）与官方仓库：跟踪器为每个目标维护 7 维状态（位置、长宽、比例、速度），预测阶段用恒速运动模型，关联阶段用 IoU 距离的代价矩阵交给匈牙利算法求全局最优分配——官方代码 `sort.py` 仅数百行，是 42.4.2 匈牙利匹配与 42.4.3 ID 管理的最佳阅读材料。论文的消融结论也值得记住：只靠「运动 + 关联」即可在 KITTI 上达到当时最优 MOTA，而 ID switch 主要来自长时间遮挡——这正是 42.4.3 中「Tolerated Missed Frames」机制要解决的问题，后续 DeepSORT/SimpleTrack 等改进均沿此路线扩展。
